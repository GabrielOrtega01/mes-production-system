Objetivo General
Sistema de Control de Producción
Desarrollar un sistema MES que permita mejorar el seguimiento de actividades en una planta manufacturera, facilitando el control de órdenes de producción, la trazabilidad de productos y el análisis de la información generada.
OE1 · Seguimiento
Órdenes y Trazabilidad
Facilitar el seguimiento de las órdenes de producción y los productos fabricados, conociendo el estado y avance de los procesos y manteniendo un registro de información por producto.
OE2 · Control
Información de Producción
Mejorar el control de la información generada durante la producción: funcionamiento de equipos, tiempos de producción y control de calidad.
OE3 · Decisiones
Apoyo a Decisiones
Proporcionar información organizada para la toma de decisiones, identificando dificultades en el proceso productivo y analizando el desempeño general.

S14 · Comportamiento
State
Estado · Máquina de estados
OE1 OE2
ContextoMaquina delega su comportamiento al estado actual: IDLE → PRODUCIENDO → FALLA → IDLE. Las transiciones son automáticas y el contexto no sabe qué hace cada estado.
Ver implementación ▼
// Context public class ContextoMaquina { private EstadoMaquina estado = new EstadoIdle(); public void iniciar() { estado.iniciar(this); } public void reportarFalla(String causa) { estado.reportarFalla(this, causa); } } // Estados: IDLE → PRODUCIENDO → FALLA → IDLE // Ciclo de vida de la maquina de manufactura
→ Resuelve OE1: ciclo de vida explícito de máquinas y órdenes

S12 · Comportamiento
Chain of Responsibility
Cadena de Responsabilidad
OE1 OE2
GestorOrdenes encadena ValidadorStock → ValidadorCapacidad → ValidadorPrioridad. Cada validador decide rechazar o pasar al siguiente, sin acoplamiento entre ellos.
Ver implementación ▼
// Handler interface public interface ValidadorOrden { void setSiguiente(ValidadorOrden sig); ResultadoOrden validar(OrdenProduccion orden); } // Cadena construida en GestorOrdenes: // Stock → Capacidad → Prioridad ResultadoOrden r = gestor.validar(orden); // Si stock < cantidad → RECHAZADA (ValidadorStock) // Si cap < cantidad → RECHAZADA (ValidadorCapacidad) // Si saturado+NORMAL → RECHAZADA (ValidadorPrioridad) // En cualquier otro caso → APROBADA ✓
→ Resuelve OE1: validación automática antes de crear la orden

S13 · Comportamiento
Iterator
Iterador · Recorrido sin exponer estructura
OE1 OE3
ColeccionLotes expone dos iteradores: FIFO (orden de llegada) y por prioridad (1=alta, 3=baja). Los clientes no conocen la estructura interna de la colección.
Ver implementación ▼
ColeccionLotes col = new ColeccionLotes(); col.agregar(new LoteProduccion("L001", "PIEZA-X", 100, 2)); col.agregar(new LoteProduccion("L002", "PIEZA-Y", 50, 1)); // FIFO: L001, L002 for (LoteProduccion l : col) { ... } // Por prioridad: L002 (P1), L001 (P2) Iterator<LoteProduccion> it = col.iteratorPorPrioridad();
→ Resuelve OE1: recorrido sistemático de órdenes sin exponer internos
→ Resuelve OE3: generación de reportes ordenados por criterio

S14 · Comportamiento
Visitor
Visitante · Operaciones sin modificar clases
OE2 OE3
VisitanteOee y VisitanteCostos recorren la estructura MaquinaElement / LineaElement sin modificar ninguna de esas clases. Nuevos informes = nuevos Visitors.
Ver implementación ▼

→ Resuelve OE2: análisis de OEE y costos sin tocar el modelo
→ Resuelve OE3: generación de reportes extensibles y desacoplados

Interpreter
Intérprete · Reglas de negocio evaluables

ExpresionAnd / ExpresionOr componen reglas de alerta: "OEE < 75% AND temperatura > 80°C → alerta". Las reglas son configurables sin recompilar.
Ver implementación ▼
ContextoAlerta ctx = new ContextoAlerta(); ctx.set("OEE", 0.65); ctx.set("Temperatura", 85.0); ExpresionAlerta regla = new ExpresionAnd( new ExpresionOEE(0.75), // OEE < 75%? new ExpresionTemperatura(80.0) // Temp > 80°C? ); // regla.interpretar(ctx) == true → emitir alerta ✓
→ Resuelve OE2: reglas de alerta configurables para equipos
→ Resuelve OE3: análisis automático con lógica de negocio compuesta
